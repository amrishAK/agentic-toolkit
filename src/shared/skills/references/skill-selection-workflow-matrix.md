## Task-specific skills

| Task area | Task signal | Skill |
|---|---|---|
| Product planning | Product purpose, priorities, roadmap, release goals, scope trade-offs, or acceptance planning | [product-planning-workflow](../../../suites/engineering/skills/design-and-planning/product-planning-workflow.md) |
| Feature design | Detailed requirements, public contracts, edge cases, acceptance criteria, or implementation plans | [feature-design-workflow](../../../suites/engineering/skills/design-and-planning/feature-design-workflow.md) |
| Architecture | Component boundaries, dependency direction, public interfaces, lifecycle, data flow, storage/protocol choices, or compatibility trade-offs | [architecture-workflow](../../../suites/engineering/skills/design-and-planning/architecture-workflow.md) |
| Code implementation and review | Implementing, fixing, refactoring, or reviewing code across languages | [code-quality-workflow](../../../suites/engineering/skills/implementation/code-quality-workflow.md) |
| Debugging | Diagnosing code, build, or CI failures using evidence and reproductions | [debugging-workflow](../../../suites/engineering/skills/implementation/debugging-workflow.md) |
| Unit testing | Focused unit tests, contract coverage, fixtures, or regression tests | [unit-test-workflow](../../../suites/engineering/skills/testing/unit-test-workflow.md) |
| Integration testing | Real component interactions through public interfaces | [integration-test-workflow](../../../suites/engineering/skills/testing/integration-test-workflow.md) |
| End-to-end testing | Complete application journeys through external interfaces | [e2e-test-workflow](../../../suites/engineering/skills/testing/e2e-test-workflow.md) |
| Fuzz testing | Bounded fuzzing, harnesses, corpus management, or regression promotion | [fuzz-testing-workflow](../../../suites/engineering/skills/testing/fuzz-testing-workflow.md) |
| Benchmarking | Workload design, measurement, comparison, or benchmark reporting | [benchmark-workflow](../../../suites/engineering/skills/performance/benchmark-workflow.md) |
| Performance profiling | CPU, memory, contention, I/O, or asynchronous performance diagnosis | [profiling-workflow](../../../suites/engineering/skills/performance/profiling-workflow.md) |
| Build systems | Make/CMake, .NET or native build workflows, dependencies, toolchains, and build entry points | [build-system-workflow](../../../suites/engineering/skills/build-and-delivery/build-system-workflow.md) |
| CI/CD | GitHub Actions workflows, permissions, caching, artifacts, or deployment boundaries | [ci-workflow](../../../suites/engineering/skills/build-and-delivery/ci-workflow.md) |
| Container builds | Dockerfiles, BuildKit, Docker Compose, or container runtime behavior | [container-build-workflow](../../../suites/engineering/skills/build-and-delivery/container-build-workflow.md) |
| Release readiness | Versions, compatibility, package checks, provenance, SBOM/signing policy, or authorized release delivery | [release-workflow](../../../suites/engineering/skills/build-and-delivery/release-workflow.md) |
| Documentation selection | Identifying document type, owner, placement, and applicable content/structure rules before reviewing or changing a document | [documentation-selection-workflow](../documentation-selection-workflow.md) |
| Technical documentation | Writing, reviewing, or maintaining README files, guides, architecture docs, runbooks, and other technical documentation | [technical-documentation-workflow](../technical-documentation-workflow.md) |
| Project conventions | Applying or auditing repository-wide conventions, documentation layout, entry points, test tiers, and baseline files | [project-conventions](../../../suites/engineering/skills/project-standards/project-conventions.md) |
| Project setup and standardization | Inspecting and standardizing repository guidance and structure through an agreed setup process | [project-rules-workflow](../../../suites/engineering/skills/project-standards/project-rules-workflow.md) |
| Change review | Readiness assessment for a commit, pre-PR, pull request, or release in the active role's supported mode | [review-workflow](../../../suites/engineering/skills/review-and-security/review-workflow.md) |
| Security review | Authorized source security review and threat modeling | [security-review-workflow](../../../suites/engineering/skills/review-and-security/security-review-workflow.md) |

Language-specific code quality, testing, benchmarking, and source documentation are routed separately by the [Engineering language matrix](programming-language-matrix.md).
